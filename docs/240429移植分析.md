# 240429 箱体气密封机 → 本框架移植分析

> 2026-09-20 基于现场文件与远程机（100.98.251.47 / Xiezhong-W02-001）实测整理。
> 结论先行：老程序是 LabVIEW + NI OPC Servers 中转方案；本框架的分层
> （状态机 / 适配器 / 仓储 / UI）可以直接承载它，需要新增 **三菱 FX 串口适配器（COM3）**
> 与 **称重 Modbus 适配器（COM6）**，ATEQ F620 串口适配器（COM4）已现成。

## 1. 老程序现状（保留的基础用途）

当前运行版本：`\\100.98.251.47\240429箱体气密封\箱体气密机 文件夹\新建文件夹\D\220902 Labview\220902\气密封测试.vi`
（2026-08-31 仍被修改，现场 LabVIEW.exe 正开着跑；C:\ 根另有打包 EXE `气密封测试.exe`）。

功能（双工位箱体气密检测）：

1. 扫码：扫码关键词（Setup.ini `扫码关键词1=GV725`）匹配产品 → 产品型号（`产品型号1=LP`）
   → 选 ATEQ 程序号（`ATEQ程序号1..35`）。
2. 左/右两工位独立测试 ATEQ F620，读测试压力/泄漏量/结果。
3. 结果回写 PLC（左/右 合格·不合格），PLC 控制流水线分道。
4. 记录：MySQL `test.information`（同时落 information.csv 与
   检测时间/泄漏量/序号 等 txt 状态文件；合格数统计）。
5. 称重：COM6 Modbus 设备 40002 寄存器 = 不合格品箱产品重量 → 写 PLC D900。
6. 打码：合格后写 `激光打码.txt`（现场激光软件监听文件，与本框架 laser 模块同思路）。
7. 样件/复位：复位F620.vi、复位结果.vi、样件（M0467）、隔离箱初始化（M0466）。

老程序已知问题（用户口述"有 bug"，佐证）：状态 txt 文件内容串写（已选产品.txt/已选检验员.txt
内容是 ` 1.00pa` 泄漏值）、LabSQL/ADO 链路脆弱、OPC 中转层多、第一腔 NG 傻等类问题
（Morocco 基线同款缺陷已在 101 框架修正）。

## 2. 老程序通讯架构

```
                                   ┌─ Channel2: Mitsubishi FX 驱动 ── COM3 ─→ FX PLC
LabVIEW 气密封测试.vi ─ OPC DA ─→ NI OPC Servers (Simulation Driver Demo.opf)
   │                               └─ modbus: Modbus Serial 驱动 ─── COM6 ─→ 称重(40002)
   ├─ VISA 串口 Modbus RTU (CRC16, 9600 8E1) ───────────────── COM4 ─→ ATEQ F620
   │   （主 VI 里另有 Modbus TCP 192.168.7.10 路径 = F620 网口，备用/历史）
   ├─ MySQL ODBC (root/root@库test 表information)
   └─ 文件接口：扫码结果.txt / 激光打码.txt / Setup.ini / information.csv
```

### 2.1 PLC 点位表（从 Simulation Driver Demo.opf 还原，OPC 标签 ↔ FX 寄存器）

| FX 寄存器 | 信号 | FX 寄存器 | 信号 |
|---|---|---|---|
| M0000 | 左复位 | M0004 | 右合格 |
| M0001 | 左合格 | M0005 | 左不合格 |
| M0003 | 右复位 | M0006 | 右不合格 |
| M0466 | 隔离箱初始化 | M0890 | 右屏蔽气缸 |
| M0467 | 样件 | M0891 | 左屏蔽气缸 |
| D0900 | 实时重量（来自 COM6 称重 40002） | | |

OPC `modbus` 通道（COM6 称重）标签：40001/40002/40003（40002=重量，字读写）。

### 2.2 ATEQ F620

- 串口 Modbus RTU，9600 8E1，CRC16（老 VI `ATEQwriteBit气密机一.vi`、
  `ATEQwrite程序选择.vi`、`ATEQread气密机一.vi`、`ReadRealStatus气密机一.vi`）。
- 语义与 F6xx 通用映射一致：程序选择写 4xxxx、状态/结果读 4xxxx——
  本框架 `SerialAteq`（0x30 实时块、StepCode=4/5/6 驱动、FIFO 处理、
  程序写 0x0200）是同一仪器的现场验证版，直接用 COM4。

### 2.3 数据库

- 老：MySQL `test.information`，9 列：
  `检测时间, 序列号, 产品二维码, 测试压力, 泄漏量, 结果, 产品型号, ATEQ程序号, 检验员`
  （LabSQL ADO + MySQL ODBC 5.3，root/root）。
- 远程机 mysqld 已在运行。本框架 repository（schema v2, PyMySQL, 库 test）可直接对接；
  老 9 列作为新 schema 的兼容视图/导出可选。

## 3. 移植到本框架的差异清单

| # | 差异 | 处理 |
|---|---|---|
| 1 | PLC：老=三菱 FX 经 OPC 中转；本框架=Snap7Plc(S7-200 SMART) | 新增 `FxSerialPlc`（pyserial 直发 FX 编程口协议，读 BR/WR、位写 BW、字写 WW）+ `FakeFxPlc`；`plc.py` 的适配接口不变 |
| 2 | 称重：COM6 Modbus 40002 → PLC D900 | 新增轻量 `WeightScale`（Modbus RTU fn03 单寄存器），状态机周期里写 D0900 |
| 3 | 点位表：points.toml 现为 S7 占位 | 用 §2.1 表格重写（FX 格式 `M0.0`/`D900`），左侧信号不做的留空 |
| 4 | 流程：老=扫码选程序、单次测试；101=无扫码、正压+负压两腔 | 需确认（见 §4 待定项） |
| 5 | 激光：老=写 激光打码.txt | 本框架 LaserMarker 即等价实现（字段模板可对齐老 8 字段） |
| 6 | 双工位：老=一台电脑管左右两工位；101=A/B 两台电脑各管一工位 | 需确认部署形态（见 §4 待定项） |
| 7 | 互斥：老 LabVIEW 正在占用 COM3/COM4 | 切换联调前必须先停老程序，避免双主站冲突 |

## 4. 待定项（需要用户拍板）

1. **PLC 通路**：Python 直连 COM3（FX 编程口协议，推荐，去 OPC 中间件）vs 保留 NI OPC Servers 做桥。
2. **生产流程**：保留扫码（关键词→程序号，记录产品二维码）vs 101 的无扫码时间戳身份；单次测试 vs 正压+负压两腔。
3. **部署**：一台电脑管左右两工位（老形态）vs A/B 两台各管一工位（101 形态）。
