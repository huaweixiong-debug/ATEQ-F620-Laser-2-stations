# 部署手册 — ATEQ F620 双腔气密检测 + 激光打码

适用：A、B 两台现场电脑（Windows 11，各配 S7-200 Smart PLC、ATEQ F620 双腔、激光打码机各一套）。
两台电脑部署步骤完全相同，仅 `config/live.toml` 中 `station`、`plc_ip`、`ateq_com` 不同。

## 0. 出厂前确认清单

| 项目 | 内容 |
|---|---|
| PLC 点位表 | ⚠️ **电气点位表到位后**填 `config/points.toml`（当前为占位地址），并核对 `laser_start`（必需）/ `laser_done`（可选） |
| ATEQ | 逐台确认 COM 口与从站地址（F620 出厂 9600 8/E/1；上位机走 Modbus 风格帧，实时块 0x0030） |
| 激光打码软件 | 确认监听文件方式：文件名、编码（默认 GBK）、每行字段顺序（默认 日期/型号/压力1/泄漏1/压力2/泄漏2/结果/操作工）、触发后是否需要 PLC 完成位反馈 |
| 网络 | 两台电脑静态 IP（同一网段，如 192.168.1.10/11）；各自 PLC、ATEQ 接本机网段 |
| 生产模式 | 生产仅允许 **Dual Test（双测）**；单测打码在数据库结构/契约另行批准前不得部署 |

## 1. 软件安装（每台电脑）

```bat
D:\> git clone https://github.com/huaweixiong-debug/ATEQ-F620-Laser-2-stations.git ATEQ
D:\ATEQ> python -m venv .venv          :: Python 3.10
D:\ATEQ> .venv\Scripts\pip install PySide6 PyMySQL pyserial python-snap7 pytest
```

## 2. MySQL 8.4（每台电脑各装一份，相互独立）

```bat
:: 管理员 PowerShell
powershell -NoProfile -ExecutionPolicy Bypass -File D:\ATEQ\tools\install_mysql84.ps1
mysql -u root -p < D:\ATEQ\tools\mysql_schema.sql
```

- schema v2 建库 `test`，表 `info_A` + `info_B`（两表结构相同；本实例只写自己的表）。
- 创建最小权限应用账号后，把凭据写入
  `C:\ProgramData\LaserLeakTest\db.json`：`{"user":"...","password":"..."}`。
- 校验：`SHOW CREATE TABLE test.info_A;` 必须含 `marked`、`Mark Time`、`cycle_id` 唯一键，
  且**不含** `Serial No.`/`2D Code`（预检会拦截旧结构）。

## 3. 数据目录与激光目录

```bat
D:\ATEQ> .venv\Scripts\python tools\prepare_production_data.py --force
```

- `D:\data\日期设置.ini`：型号参数（型号/客户编号/日期方案/ATEQ程序号），可在 UI 设置页维护。
- `D:\data\日期对照.ini`：日期方案映射（打码文本"日期"字段格式）。
- `D:\data\作业员列表.txt`、`D:\data\管理员.txt`（首行 = admin 密码；现场已统一为 `0000`）。
- `D:\激光打码.txt`：**激光打码软件监听此文件**（101 流程统一输出路径）。

## 4. 配置 `config/live.toml`（A/B 电脑各改三处）

```toml
station = "A"            # A 电脑 "A"；B 电脑 "B"
plc_ip = "192.168.1.20"  # 本工位 PLC IP
ateq_com = "COM6"        # 本工位 ATEQ 串口
ateq_slave = 1
ports_confirmed = true   # 串口逐台确认后置 true
points_confirmed = false # 点位表核对完成前保持 false（LIVE 会被拦截）
```

## 5. PLC 点位表（等电气点位表）

编辑 `config/points.toml`，格式 `信号 = "M字节.位"`。必填信号：
`start/reset/calibration/ng_sample/ok_sample/manual/block/stamp/clamp/transfer/pressure/door_disable/laser_start`，
可选 `laser_done`（打码完成反馈，配置 `laser_wait_done = true` 时启用）。

⚠️ 逐点与电气图纸核对后，在 `live.toml` 置 `points_confirmed = true`。
点位写使能受 CapabilityPolicy 控制，只有 LIVE 装配会 `enable_writes(True)`。

## 6. 激光打码软件设置（每台电脑）

- 监听文件：`D:\激光打码.txt`（GBK，CRLF，8 行，打码后 10 秒程序自动清空）。
- 触发：PLC `laser_start` 位（上位机置位 **2 秒**后复位，参数 `laser_hold_seconds`/`laser_settle_seconds` 可调）；**UI 启动时强制清零本工位打码位**，清零失败拒绝启动（fail-closed）。
- 若激光控制器支持"打码完成"输出 → 接 PLC，填 `points.toml` 的 `laser_done` 并置 `laser_wait_done = true`。

## 7. 预检与启动

```bat
:: 预检（只读，不动设备状态）
D:\ATEQ> .venv\Scripts\python -m app.main --config config\live.toml --preflight

:: 预检全 PASS 后启动
D:\ATEQ> run_live_ui.bat
```

预检项：PLC 点位表加载与人工确认 → PLC 102 端口 + 点位读回 → ATEQ 串口 →
激光监听目录可写 → 型号/日期方案可解析 → MySQL 结构校验。
任一项 BLOCKED 即拒绝进入 LIVE（fail-closed）。

单机诊断：`--ateq-test --port COM6 --slave 1`（只测 ATEQ 串口）；
`--diagnose --device all`（无副作用）。

### 7.1 B 电脑一键拉起 A 电脑 UI（101 流程）

A 的 PLC 读写经 B 中转，B 必须先启动。B 的 `run_live_ui.bat` 在 relay
就绪后会自动经 SSH（`dell@192.168.7.10`）触发 A 的**桌面** UI
（交互式计划任务 `ATEQ_A_UI`，否则 SSH 直启只会落在后台会话、操作员看不到）。

一次性配置（每台新机）：
1. A 电脑：运行 `D:\ATEQ\tools\install_a_ui_task.cmd`（创建交互式计划任务）。
2. B 电脑：确保 `C:\Users\dell\.ssh\id_ed25519_ateq` 存在，且其公钥已加入
   A 的 `C:\ProgramData\ssh\administrators_authorized_keys`
   （该文件权限仅 `Administrators` 与 `SYSTEM`）。

日常操作：A、B 均登录桌面后，只需在 **B** 双击 `run_live_ui.bat`。
若自动拉起失败（SSH/任务异常），仍可在 A 机桌面直接双击 `run_live_ui.bat`。

## 8. 试产流程（shadow → live）

> **前置强制条件：生产模式 = Dual Test（双测）。** LIVE 下若选择单测，周期在启动前
> 会被拒绝并在卡片上提示 `single_mode_unsupported`（请切换 Dual Test）。
> schema v2 不保存检测模式（`test_mode` 回读恒为 `dual`），单测打码在数据库结构/
> 契约另行批准前**不得部署**；校准 NG/OK 样件流程不受影响（样件默认不打码）。

1. 首次启动校准灯亮（校准到期）→ 按"启动验证"→ 依次放 NG、OK 样件完成验证。
2. 正常生产：放件 → 按 PLC 启动（或设备自动）→ 两次测试 → 双合格自动打码 →
   10 秒后打码文件自毁 → 界面"打码"列显示 √。第一腔 NG 时仪器自行终止、
   该件直接记录 NG 不打码，下一件正常启动。
3. 重打码（管理员）：卡片上"重打码"按钮，对已完成周期重新写文件+脉冲。
4. 查询/导出：查询页按时间/型号/结果筛选，可导出 CSV。

## 9. 常见问题

| 现象 | 处理 |
|---|---|
| 预检"PLC 点位表"BLOCKED | points.toml 未填/未确认；等电气点位表并核对 |
| 预检"MySQL"BLOCKED 提示"扫码版表结构" | 库是旧 schema，重跑 `tools/mysql_schema.sql` |
| 激光机不打码 | 核对监听文件路径/编码/换行；用"重打码"验证文件是否更新；核对 laser_start 点位 |
| 打码内容乱码 | 打码软件编码与 `laser_encoding`（默认 gbk）不一致 |
| StepCode 不跳变 | ATEQ 从站地址/COM 口不对，用 `--ateq-test` 排查 |
| 界面提示 RECOVERY_REQUIRED | 断电/故障残留周期，管理员在"手动"页归档 |
| 提示 `single_mode_unsupported` | LIVE 选中了单测（Single Test）：切换到 Dual Test / 双测后重新启动周期；单测打码需数据库结构/契约批准后才能部署 |
